Where each signal would come from

Search interestGoogle Travel Analytics for eligible partners, or licensed OTA search trend data. Not connected here.
Booking paceThe host’s own bookings and calendar through an approved integration or upload. Platform-wide OTA bookings require a separate licensed source.
Nearby supplyAuthorized same-date rates and availability from comparable stays. Booking.com and Agoda document partner search APIs; access and permitted use must be confirmed.
Local eventsPublished calendars with event date, distance, source and update time.
No live partner feedsNo measured accuracy yet
Why hotels are a supporting signal

Nearby hotel searches may indicate destination demand, but a 12-guest villa serves a different trip. The model should learn how strongly hotel signals predict bookings for comparable homes.

What is an assumption or future integration

  • The ₹10,000 pool premium is a user-suggested scenario input, not an observed nearby rate difference.
  • No nearby price set, accommodation search series, platform-wide booking trend or upcoming event has been verified for this concept. The demand slider values are hypothetical.
  • Google Travel Analytics ↗ documents accommodation search trends for eligible partners. Booking.com Demand API ↗ and Agoda Demand API ↗ document search, rates or availability for approved partners; these pages do not establish access to platform-wide search or booking counts for Revenue Twin.
  • Real account connection requires an approved Airbnb software integration. This demo does not request credentials.
